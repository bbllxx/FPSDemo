僵尸特殊技能组件设计

本文档基于当前 FPSDemo 源码设计一套轻量级技能组件系统。目标是在不引入 GAS 的前提下， 让重型、轻型、远程僵尸分别拥有可配置、可被行为树调度、可由动画通知结算的特殊技能。

适用模块 Source/FPSDemo
推荐方案 ActorComponent + BT Task/Decorator + AnimNotify
文档日期 2026-05-13

概览

推荐新增一个抽象基础组件 UZombieSkillComponent，由它统一处理技能冷却、释放条件、释放状态、 动画事件入口和结算时机。每种僵尸再挂载一个具体技能组件，例如 UHeavySlamSkillComponent、ULightPounceSkillComponent、 URangedVolleySkillComponent。

行为树只负责判断“现在是否应该释放技能”；组件负责“技能如何释放”；动画蓝图负责播放表现； AnimNotify 负责在关键帧调用组件结算效果。这个分工和当前普通攻击流程保持一致， 能减少对 AZombieBase、AZombieAIController 和现有行为树的侵入。

设计结论： 当前项目不建议直接上 Gameplay Ability System。GAS 适合复杂属性、Buff、标签、网络同步和大量技能组合； 本项目目前是单机 FPS 僵尸玩法，轻量组件更容易实现、调试和毕业设计展示。

已确认项目上下文

现有代码 已确认行为 对技能系统的影响
AZombieBase 维护生命、普通攻击、攻击冷却、攻击范围、目标引用、受伤和死亡流程。 技能组件应复用 TargetPlayer，不要重复维护另一套目标选择逻辑。
TryStartAttack() / CommitAttackDamage() 普通攻击先触发动画，随后由动画通知调用结算函数。 特殊技能也应采用“发起技能 - 播放动画 - 通知结算”的节奏。
UAnimNotify_ZombieCommitAttackDamage 动画通知从 Mesh Owner 转成 AZombieBase 后调用伤害结算。 可以新增 UAnimNotify_ZombieCommitSkill，调用技能组件的 CommitSkillEffect()。
UBTTask_Attack 行为树任务只调用 TryStartAttack()，立即返回成功或失败。 技能任务也应保持短任务，不在 BT Task 内 Tick、等待动画或循环冷却。
UBTDecorator_InAttackRange / UBTDecorator_ZombieAttackCooldown 行为树通过 Decorator 判断攻击距离和冷却。 新增技能 Decorator 时也只做条件判断，执行逻辑交给组件。
AHeavyZombie、ALightZombie、ARangedZombie 三类僵尸通过子类设置不同血量、速度、攻击范围和特殊属性。 具体技能组件可以在各自子类构造函数中创建，保持类型差异集中。

整体架构

技能系统建议分成四层：僵尸基类持有组件，具体技能组件实现效果，行为树负责调度，Blueprint 和动画资产负责表现。 组件不主动决定什么时候释放技能，避免把 AI 决策散落到组件 Tick 中。 

Behavior Tree
  ├─ BTDecorator_ZombieSkillReady
  ├─ BTDecorator_ZombieSkillRange
  └─ BTTask_UseZombieSkill
        │
        ▼
AZombieBase
  ├─ TargetPlayer
  ├─ 普通攻击流程
  └─ SpecialSkillComponent : UZombieSkillComponent
        │
        ├─ UHeavySlamSkillComponent
        ├─ ULightPounceSkillComponent
        └─ URangedVolleySkillComponent
              │
              ▼
Animation Blueprint / Montage / AnimNotify
  └─ UAnimNotify_ZombieCommitSkill → CommitSkillEffect()

第一阶段结构

每个僵尸只有一个特殊技能，因此使用一个 SpecialSkillComponent 即可。 技能参数可以先写成 UPROPERTY(EditDefaultsOnly)，之后再抽出 DataAsset。

后续扩展结构

当出现 Boss、多技能精英怪或随机技能组合时，再把组件升级为技能管理器， 用 TArray<UZombieSkillComponent*> 或技能 DataAsset 管理多技能。

核心类职责

类 / 资源 职责 不负责
AZombieBase 持有 SpecialSkillComponent 指针，提供目标、控制器、位置、普通攻击和死亡状态。 不写具体技能效果，不决定技能释放优先级。
UZombieSkillComponent 统一处理冷却、目标检查、释放状态、动画事件入口、提交和取消。 不做玩家感知，不直接修改行为树，不做复杂 AI 决策。
UHeavySlamSkillComponent 实现重型僵尸范围重击、击退和范围伤害。 不修改重型僵尸的常驻减伤逻辑。
ULightPounceSkillComponent 实现轻型僵尸跳扑、短时冲刺、命中结算。 不替代基础追击移动，不长期接管 CharacterMovement。
URangedVolleySkillComponent 实现远程僵尸连射、毒液弹或区域压制。 不继续扩大 ARangedZombie::TryStartAttack() 的职责。
BTTask_UseZombieSkill 从 AIController 取 Pawn，调用 TryStartSkill()，并返回成功或失败。 不等待动画，不循环检查冷却，不直接造成伤害。
BTDecorator_ZombieSkillReady 判断技能组件是否存在、冷却是否结束、是否已有技能待结算。 不启动技能。
UAnimNotify_ZombieCommitSkill 在动画关键帧调用 CommitSkillEffect()。 不写具体技能效果，不判断是否该放技能。

组件接口设计

基础组件建议放在 Public/Character/Zombies/Components/ZombieSkillComponent.h 和 Private/Character/Zombies/Components/ZombieSkillComponent.cpp。它应是抽象组件， 但接口保持 Blueprint 可读，便于动画蓝图和调试面板查看状态。

建议字段

字段 类型 用途
SkillName FName 技能标识，例如 HeavySlam、LightPounce。
SkillRange float 技能释放距离，用于行为树 Decorator 和组件自身二次校验。
SkillCooldown float 技能冷却时间，独立于普通攻击冷却。
LastSkillTime float 上次释放时间，初始值建议为 -SkillCooldown，确保开局可释放。
bSkillEffectPending bool 技能已发起但尚未由动画通知结算时为 true。
bLockMovementDuringSkill bool 技能前摇期间是否停止 AI 移动，重击和远程连射通常需要。
SkillMontage TObjectPtr<UAnimMontage> 可选配置。也可以继续由 BlueprintImplementableEvent 播放动画。

建议函数契约

bool CanStartSkill() const;
bool IsTargetInSkillRange() const;
bool TryStartSkill();
float CommitSkillEffect();
void CancelSkill();
float GetCooldownRemaining() const;
AZombieBase* GetOwnerZombie() const;
AActor* GetTargetActor() const;
关键约束： TryStartSkill() 只负责进入技能释放状态和触发表现，不应直接造成最终伤害。 真正伤害、击退、生成投射物或区域效果应放在 CommitSkillEffect() 中，由动画通知调用。

主要流程

1
AZombieAIController 通过感知系统发现玩家，并把 Target 写入 Blackboard， 同时同步到 AZombieBase::TargetPlayer。
2
行为树在攻击分支之前或并列分支中检查 BTDecorator_ZombieSkillReady 和 BTDecorator_ZombieSkillRange。
3
BTTask_UseZombieSkill 调用 SpecialSkillComponent->TryStartSkill()。 组件记录释放时间，设置 bSkillEffectPending，触发 Blueprint 事件或播放 Montage。
4
动画播放到命中帧时触发 UAnimNotify_ZombieCommitSkill， 通知组件执行 CommitSkillEffect()。
5
具体技能组件执行伤害、击退、冲刺落点检测、投射物生成或区域效果，然后清除 pending 状态。
6
冷却期间 Decorator 返回 false，行为树继续走追击、普通攻击、巡逻或等待分支。

Behavior Tree 接入

当前行为树已经使用 Target、State、HomeLocation 等 Blackboard 键。 特殊技能可以先复用 Target，只新增行为树节点，不强制新增 Blackboard 键。

节点 建议行为 返回规则
BTDecorator_ZombieSkillReady 检查 Pawn 是否为 AZombieBase，是否存在技能组件，组件是否可释放。 可释放返回 true，否则 false。
BTDecorator_ZombieSkillRange 调用组件 IsTargetInSkillRange()，允许不同技能拥有不同释放距离。 在范围内返回 true，否则 false。
BTTask_UseZombieSkill 可选把 State 写为 Skill，再调用 TryStartSkill()。 技能成功发起返回 Succeeded，否则 Failed。
推荐行为树优先级： 有目标时先判断特殊技能；技能不可用时走普通攻击；普通攻击不在范围内时走追击；无目标时巡逻。 这样特殊技能会自然成为“偶发强动作”，不会破坏普通攻击循环。

Blueprint 接入方式

当前 AZombieBase 已通过 BlueprintImplementableEvent 把普通攻击、受伤、死亡表现交给蓝图。 技能系统也建议保留同样风格：C++ 管逻辑边界，Blueprint 管动画、特效和音效。

接入点 Blueprint 需要做的事 注意事项
技能动画 为每种僵尸配置特殊技能 Montage 或在事件中播放对应动画。 动画命中帧必须放置 Zombie Commit Skill 通知。
技能表现 在技能开始事件中播放前摇、音效、粒子或镜头反馈。 表现不要直接造成伤害，伤害由组件结算。
远程技能投射物 为远程技能设置专用 Projectile Blueprint。 当前 AFPSDemoProjectile 不会对僵尸或玩家直接造成伤害，远程技能需要专用投射物或命中伤害组件。
行为树资产 在现有攻击分支附近新增技能 Decorator 和技能 Task。 节点排布应按“技能判断 → 技能释放 → 普通攻击/追击”分层，避免节点重叠。

三类僵尸技能方案

Heavy Zombie

震荡重击

重型僵尸进入短前摇，命中帧对前方或周围小半径范围内玩家造成高伤害和强击退。 适合强化“正面对抗压迫感”。

范围伤害 强击退 长冷却
组件UHeavySlamSkillComponent
距离约 300-450
冷却约 8 秒
结算动画通知时检测范围并调用 ApplyDamage 和 LaunchCharacter
Light Zombie

跳扑突袭

轻型僵尸在中距离快速扑向玩家，落地或命中帧结算伤害。它补足轻型僵尸血少但机动性强的定位。

位移 短前摇 追击补强
组件ULightPounceSkillComponent
距离约 350-900
冷却约 5 秒
结算发起时计算方向，短时冲刺；通知时若目标仍接近则造成伤害
Ranged Zombie

毒液连射

远程僵尸在理想距离内连续发射数枚较慢投射物，形成区域压制。它和现有远程普通攻击区分开来。

多投射物 区域压制 远距离
组件URangedVolleySkillComponent
距离约 900-2000
冷却约 7 秒
结算通知时从 MuzzleLocation 或组件配置点生成投射物

扩展入口

要扩展的内容 优先修改位置 原因
新增一种僵尸技能 Public/Character/Zombies/Components 和 Private/Character/Zombies/Components 每个具体技能组件只处理自己的释放和结算逻辑，避免污染基类。
调整技能参数 具体技能组件的 UPROPERTY(EditDefaultsOnly) 或后续 UZombieSkillDataAsset 参数应允许蓝图子类覆盖，便于调平衡。
改变技能释放策略 Behavior Tree 和技能 Decorator 释放策略属于 AI 决策，不应写进组件 Tick。
改变命中时机 Animation Montage 的 Notify 位置 时机和动画强相关，应由动画资产控制。
支持多个技能 把 SpecialSkillComponent 扩展为技能数组或新增 UZombieSkillManagerComponent 当前设计保留升级路径，但第一阶段不需要多技能管理复杂度。

建议实现顺序

  1. 新增基础 UZombieSkillComponent，只实现冷却、目标检查、pending 状态和空的 CommitSkillEffect()。
  2. 在 AZombieBase 增加技能组件访问接口，例如 GetSpecialSkillComponent()。
  3. 先实现 UHeavySlamSkillComponent，因为它不依赖投射物系统，验证路径最短。
  4. 新增 UAnimNotify_ZombieCommitSkill，用重型僵尸动画验证结算时机。
  5. 新增 BTDecorator_ZombieSkillReady、BTDecorator_ZombieSkillRange、BTTask_UseZombieSkill。
  6. 接入行为树资产，确认技能释放优先级不会阻塞普通攻击和追击。
  7. 再实现轻型跳扑和远程连射，分别处理位移和投射物的特殊情况。

测试与验证

验证项 建议方式 通过标准
组件冷却 新增自动化测试或在 PIE 中输出调试日志。 冷却中 CanStartSkill() 返回 false，冷却结束后返回 true。
动画通知结算 在技能动画关键帧放置 Notify。 技能发起后不会立即伤害玩家，只在 Notify 到达时结算。
行为树优先级 观察 BT 调试器中技能分支、普通攻击分支和追击分支的切换。 技能可用时释放技能；不可用时仍能正常普通攻击或追击。
死亡中断 技能前摇期间击杀僵尸。 死亡后技能不会继续结算，组件 pending 状态被取消或 Owner 无效时安全返回。
远程投射物伤害 使用专用投射物 Blueprint 或 C++ Actor 测试命中玩家。 投射物命中玩家时能造成预期伤害，并不会误伤发射者。

编辑器目标编译命令仍使用项目既有 FPSDemoEditor Win64 Development 构建方式。 技能组件本身只依赖当前模块已有的 Engine、AIModule、GameplayTasks 和 NavigationSystem，第一阶段通常不需要修改 FPSDemo.Build.cs。
