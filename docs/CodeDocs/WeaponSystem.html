武器系统说明

本文档说明当前 C++ 枪械武器系统的整体架构、类职责、运行流程和 Blueprint 接入方式。 系统在原有投射物武器之外新增了基于 LineTrace 的枪械逻辑，支持爆头判定、共享备弹、槽位切换和拾取物接入。

核心检测 LineTraceSingleByChannel
伤害入口 UGameplayStatics::ApplyPointDamage
数据配置 UWeaponDataAsset

运行链路

输入Enhanced Input 触发开火、换弹、切枪。
角色AFPSDemoCharacter 只做输入转发。
库存UWeaponInventoryComponent 管理当前武器和弹药。
武器AWeaponBase 执行 LineTrace 和伤害计算。
目标命中僵尸 SkeletalMesh，读取 BoneName。
伤害ApplyPointDamage 传递给 AZombieBase。
模块 职责 不负责的事情
AFPSDemoCharacter 绑定输入，把玩家操作转发给库存组件。 不计算伤害，不直接执行射线。
UWeaponInventoryComponent 持有武器、切枪、共享备弹、进入和完成换弹。 不关心具体枪械弹道和爆头规则。
AWeaponBase 单把枪的开火、射线、散布、爆头、伤害和表现事件。 不管理其他槽位武器。
UWeaponDataAsset 保存枪械参数，让不同枪械复用同一套 C++ 行为。 不包含运行时状态。
AWeaponPickup 处理世界拾取，生成武器实例并交给库存。 不直接装备到角色网格体。
AZombieBase 提供可命中的 Mesh 碰撞和受伤扣血逻辑。 不判断枪械是否爆头。

核心类型

EWeaponSlot

定义武器槽位：None、Primary、Secondary、Special。同一槽位只保留一把武器，新武器加入同槽位时会替换旧武器。

EWeaponAmmoType

定义弹药类型：None、Rifle、Pistol、Shell。备弹按弹药类型共享，而不是按单把武器保存。

EWeaponFireMode

定义开火模式：SemiAuto 为按下一次开一枪，FullAuto 为按住后通过定时器持续开火。

射线通道： FPSDemoWeapon::WeaponTraceChannel 封装了 ECC_GameTraceChannel2，对应项目配置里的 WeaponTrace。这样代码中不会散落硬编码通道编号。

武器数据：UWeaponDataAsset

UWeaponDataAsset 保存一把枪的全部可配置参数。C++ 只实现通用行为，具体步枪、手枪、霰弹枪等差异由数据资产控制。

字段 作用
WeaponId武器标识。
Slot武器占用的槽位。
AmmoType使用哪一种共享备弹。
FireMode半自动或全自动。
MagazineCapacity弹匣容量。
InitialReserveAmmo拾取时加入的初始备弹。
MaxReserveAmmo对应弹药类型的备弹上限。
BaseDamage基础伤害。
HeadshotMultiplier爆头伤害倍率。
RangeLineTrace 射程。
FireInterval两次开火之间的最小间隔。
ReloadDuration换弹时长配置，当前主要供 Blueprint 动画或后续 C++ 定时器接入。
PelletsPerShot每次开火生成的弹丸数量，霰弹枪可设为大于 1。
SpreadAngleDegrees弹丸散布角度。
FireSound开火音效。
 
默认配置倾向于步枪：
弹匣 30
初始备弹 90
基础伤害 25
爆头倍率 2
射程 8000
开火间隔 0.12
单发弹丸 1
无散布

枪械基类：AWeaponBase

AWeaponBase 是所有枪械的 C++ 基类，负责单把武器的实际战斗逻辑。

组件

  • WeaponMesh：USkeletalMeshComponent，用于武器模型。
  • MuzzlePoint：UArrowComponent，用于枪口方向和非玩家持有者的射线起点回退。

玩家开火以相机为准，不直接从枪口发射，避免准星和枪口模型偏移造成命中不一致。

运行状态

  • WeaponData：当前武器的数据资产。
  • CurrentMagazineAmmo：当前弹匣子弹数。
  • bReloading：是否正在换弹。
  • OwnerCharacter：持有者角色。
  • OwningInventory：所属库存组件。
  • LastFireTime：射速限制依据。
  • AutoFireTimerHandle：全自动开火定时器。

开火入口

StartFire()
  -> FireOnce()
    -> GetOwnerViewpoint()
    -> FireFromViewpoint()
函数 职责
StartFire() 检查武器数据，立即开第一枪；全自动模式下启动定时器持续调用 HandleAutoFire()。
StopFire() 清理全自动开火定时器，半自动武器调用也安全。
CanFire() 检查武器数据、换弹状态、弹匣子弹和 FireInterval。
FireFromViewpoint() 执行实际 LineTrace，并对每条弹丸独立结算命中和伤害。

射线逻辑

Start = 相机位置
Direction = 相机前向
End = Start + Direction * WeaponData.Range
Channel = FPSDemoWeapon::WeaponTraceChannel

射线查询会忽略武器自身、持有者角色和武器 Owner，避免第一人称手臂、玩家胶囊体或武器模型挡住自己的枪线。

散布、爆头和伤害

霰弹散布

BuildShotDirections() 根据 PelletsPerShot 和 SpreadAngleDegrees 生成弹丸方向。散布大于 0 时使用 FMath::VRandCone。

爆头规则

IsHeadshotBone() 判断骨骼名是否包含 head，忽略大小写。爆头伤害为 BaseDamage * HeadshotMultiplier。

ApplyDamageToHit() 从 HitResult 获取命中 Actor，必要时回退到命中组件的 Owner，然后调用 UGameplayStatics::ApplyPointDamage 传递最终伤害和完整命中信息。

Blueprint 扩展事件

  • ReceiveWeaponFired(const FHitResult& Hit, bool bHeadshot)：播放枪口火光、开火动画、后坐表现和命中特效。
  • ReceiveReloadStarted()：播放换弹动画。
  • ReceiveReloadFinished()：恢复换弹表现状态。

同时提供 OnWeaponFired、OnReloadStarted、OnReloadFinished 委托，便于 UI 或其他系统监听武器状态变化。

库存组件：UWeaponInventoryComponent

该组件挂在玩家角色上，管理武器槽位、当前武器、共享备弹、切枪和换弹。

持有的武器槽

  • PrimaryWeapon
  • SecondaryWeapon
  • SpecialWeapon
  • CurrentWeapon
  • CurrentSlot

备弹存储

TMap<EWeaponAmmoType, int32> ReserveAmmoByType

备弹按弹药类型共享。两把使用 Rifle 的武器会消耗同一个步枪弹药池。

添加武器流程

  1. 检查武器和 WeaponData 是否有效。
  2. 根据 WeaponData.Slot 找到目标槽位。
  3. 如果同槽位已有旧武器，先停止旧武器开火，再销毁旧武器。
  4. 初始化新武器的 Owner、Instigator 和库存引用。
  5. 把武器挂到玩家 Mesh1P。
  6. 把 InitialReserveAmmo 加入对应弹药类型的共享备弹。
  7. 当前没有武器或正在替换当前槽位时自动装备，否则隐藏新武器并广播弹药变化。

切枪与换弹

操作 关键行为
EquipWeaponSlot() 停止当前武器持续开火，隐藏旧武器，显示新武器，并广播当前武器和弹药变化。
EquipNextWeapon() / EquipPreviousWeapon() 只在已有武器的槽位之间循环。
ReloadCurrentWeapon() 只进入换弹状态，不立即搬运子弹。
FinishReloadCurrentWeapon() 按弹匣缺口从共享备弹搬运子弹，并广播弹药变化。
这种换弹设计让动画通知可以控制真正装填时机。如果换弹动画中断，只要不调用 FinishReloadCurrentWeapon()，就不会提前扣除备弹。

网络接口与 UI 事件

当前预留了 ServerStartFire()、ServerStopFire()、ServerReload()、ServerEquipSlot()。 它们目前主要转发到本地逻辑，后续多人联机需要补充状态复制、服务端命中验证和客户端预测。

UI 可监听 OnCurrentWeaponChanged 和 OnWeaponAmmoChanged，刷新武器名、弹匣子弹和备弹数量。

拾取物：AWeaponPickup

AWeaponPickup 表示世界中的武器拾取物。

组件和配置

  • PickupSphere：球形触发器，默认半径 64，碰撞 Profile 为 Trigger。
  • WeaponClass：拾取后生成的 AWeaponBase 子类。

拾取流程

  1. 玩家进入触发范围。
  2. 检查重叠对象是否为 AFPSDemoCharacter。
  3. 查找玩家身上的 UWeaponInventoryComponent。
  4. 按 WeaponClass 生成武器实例。
  5. 调用 Inventory->AddWeapon(Weapon)。
  6. 成功后移除监听并销毁拾取物，失败则销毁新生成的武器。

角色与僵尸接入

AFPSDemoCharacter

角色新增 UWeaponInventoryComponent* WeaponInventory，并在 BeginPlay() 中调用 WeaponInventory->InitializeInventory(this)。

Input Action 绑定结果
FireAction StartedStartFire()
FireAction Completed/CanceledStopFire()
ReloadAction StartedReloadWeapon()
NextWeaponAction StartedEquipNextWeapon()
PreviousWeaponAction StartedEquipPreviousWeapon()
Slot1Action / Slot2Action / Slot3Action装备主武器、副武器、特殊武器槽。

AFPSDemoPlayerController

控制器在 BeginPlay() 中加入两个输入映射：默认 InputMappingContext 使用优先级 0， WeaponInputMappingContext 使用优先级 1，便于武器输入覆盖冲突按键。

AZombieBase

枪械射线需要命中僵尸 SkeletalMesh，而不是胶囊体，因为爆头判定依赖 Hit.BoneName。 构造函数中让胶囊体忽略 WeaponTrace，让 Mesh 开启 QueryOnly 并阻挡 WeaponTrace。 

旧投射物 -> 命中胶囊体
枪械射线 -> 穿过胶囊体，命中 SkeletalMesh，读取 BoneName

碰撞通道

Config/DefaultEngine.ini 中新增 WeaponTrace 通道：

+DefaultChannelResponses=(Channel=ECC_GameTraceChannel2,Name="WeaponTrace",DefaultResponse=ECR_Block,bTraceType=True,bStaticObject=False)

代码中统一通过 FPSDemoWeapon::WeaponTraceChannel 引用该通道。

  • 新的可被枪械命中的敌人 Mesh 需要阻挡 WeaponTrace。
  • 玩家和武器自身由射线查询参数忽略，不依赖碰撞响应绕开。
  • 不应被枪械打中的对象可以把 WeaponTrace 响应设为 Ignore。

Blueprint 快速上手

1. 创建武器数据资产

  1. 基于 UWeaponDataAsset 创建数据资产。
  2. 配置 Slot：步枪用 Primary，手枪用 Secondary，霰弹枪或特殊武器用 Special。
  3. 配置 AmmoType：步枪 Rifle，手枪 Pistol，霰弹枪 Shell。
  4. 配置伤害、射程、弹匣、备弹和开火间隔。
  5. 霰弹枪将 PelletsPerShot 设为大于 1，并设置 SpreadAngleDegrees。
  6. 需要开火音效时设置 FireSound。

2. 创建武器 Blueprint

  1. 创建继承自 AWeaponBase 的 Blueprint，例如 BP_RifleWeapon。
  2. 设置 WeaponData 为对应数据资产。
  3. 给 WeaponMesh 设置武器 SkeletalMesh。
  4. 调整 MuzzlePoint 的位置和方向。
  5. 实现 ReceiveWeaponFired，播放枪口火光、动画和命中特效。
  6. 实现 ReceiveReloadStarted，播放换弹动画。
  7. 在换弹动画通知中调用角色库存组件的 FinishReloadCurrentWeapon()。

3. 配置拾取物

  1. 创建继承自 AWeaponPickup 的 Blueprint，或直接放置 AWeaponPickup。
  2. 设置 WeaponClass 为要生成的武器 Blueprint 类。
  3. 玩家进入拾取范围后会自动生成并装备武器。

4. 配置玩家输入

  1. 在玩家角色 Blueprint 中配置 FireAction、ReloadAction、切枪和槽位 Input Action。
  2. 在玩家控制器 Blueprint 中配置 InputMappingContext 和 WeaponInputMappingContext。
  3. 在 WeaponInputMappingContext 中绑定开火、换弹、切枪和槽位键位。

常见扩展方式

目标 修改点 建议
增加新武器 UWeaponDataAsset、AWeaponBase Blueprint、AWeaponPickup 如果只是参数不同，不需要新增 C++ 类。
增加新弹药类型 Public/Weapon/WeaponTypes.h 在 EWeaponAmmoType 中添加枚举，例如 Sniper，再在数据资产里选择。
增加新武器槽 EWeaponSlot、库存组件槽位成员、槽位查询函数、角色输入绑定 需要同步更新 Blueprint 输入配置。
增加后坐力或镜头抖动 ReceiveWeaponFired 或 BuildShotDirections() 纯表现放 Blueprint；影响实际弹道时扩展 C++ 弹道方向计算。
增加不同部位倍率 CalculateDamageForBone() 可改为读取骨骼名到倍率的配置表，例如 head、spine、leg。
完善多人联机 Server RPC、状态复制、命中验证、弹药同步、表现同步 服务端应权威决定开火和命中，客户端只做预测与反馈。

当前注意事项

  • ReloadDuration 当前只是配置字段，实际等待和完成换弹时机需要 Blueprint 动画通知或后续 C++ 定时器接入。
  • ReceiveWeaponFired 只收到最后一次命中结果；霰弹多弹丸已独立结算伤害，但表现层目前只广播一次。
  • 爆头规则依赖骨骼名包含 head，敌人骨骼命名不符合该规则时需要调整命名或扩展判定逻辑。
  • AWeaponBase 目前播放开火音效，枪口特效、开火动画、换弹动画主要预期在 Blueprint 事件里完成。
  • 多人 RPC 入口已经预留，但尚未形成完整网络同步方案。
合并或继续开发前，建议先确认只提交武器系统相关源码、配置和文档，避免把无关 Content 资产或临时文件一起带入提交。
