Codex 实施计划

本文件不是概念笔记，而是新项目中的执行规格。目标是从一个新的 UE5 C++ 项目开始，逐步实现精简版 Lyra 架构：Experience + GameFeature、GAS、多人服务器权威、射击、主动技能、闪避无敌帧、敌人 AI、波次关卡和计分。

交给新线程 Codex 的首要指令：先读取新项目的 AGENTS.md、.uproject、模块与插件配置，再以本文为需求源建立任务计划。不要一次性生成全部系统；严格按“分阶段实施”推进，每阶段先编译、再做多人 PIE 验证，通过后才进入下一阶段。

执行纪律

  • 只实现当前阶段需要的最小代码，不预建庞大通用框架。
  • 改动前核对实际引擎版本、模块名、现有源码和配置，不假定新项目与本 Lyra 仓库完全相同。
  • 所有伤害、死亡、AI、波次推进和计分最终由服务器裁决；客户端预测不能成为权威结果。
  • 不要直接读取或编辑 .uasset/.umap 二进制。需要资产时创建 C++ 基类，并给出明确的编辑器资产创建与属性连接清单。
  • 除非用户在新线程明确授权，不执行 Git 操作。
  • 每个阶段报告：修改文件、编辑器接入步骤、构建结果、测试结果、遗留问题。

02　已确认需求与默认决策

主题已确认方案
游戏类型多人合作 PvE 战斗 Demo，玩家与服务器生成的敌人战斗。
网络模型服务器权威；支持至少双人联机，并以 Dedicated Server 可运行作为最终目标。
架构风格精简版 Lyra：保留 Experience + 单个 Combat GameFeature Plugin，不照搬 Lyra 全部组件注入和通用系统。
GAS 范围射击、换弹、闪避和主动技能全部实现为 Gameplay Ability。
闪避GA_Dodge 使用本地预测；约 0.3 秒内由持续型 GameplayEffect 授予 State.Invulnerable，服务器伤害应用检查该标签。
关卡简单波次管理；地图保存空间内容，Experience 组装玩法，DataAsset 保存波次和计分参数。
计分默认每击杀一个敌人 +100；暂定同时记录击杀者个人分数和全队总分。若用户之后只要其中一种，删除另一种，不改变死亡判定链路。
启动假设：新项目采用 Unreal Engine 5.4 C++。如果实际版本不同，Codex 必须先按该版本 API 调整插件、模块依赖和 GAS 调用，不应机械复制 UE5.4 代码。项目名尚未确定，本文以 DemoGame 和 CombatDemo 作为占位名。

03　范围与非目标

首个可玩版本必须包含

  • 双人进入同一战斗地图；玩家角色正确初始化 ASC 与属性。
  • 普通射击、换弹、闪避和至少一项带冷却的主动技能。
  • 服务器 AI 敌人会发现、接近和攻击玩家。
  • 伤害、无敌、死亡、击杀归属、波次推进和计分均由服务器确认。
  • HUD 显示生命、技能冷却、个人分数、团队分数、当前波次和剩余敌人。
  • 一个可配置的战斗关卡 DataAsset，至少包含两波敌人。

首版明确不做

  • 完整 Lyra Inventory、Equipment、Team、Frontend、CommonSession、Replay 和 Modular Pawn 初始化状态机。
  • 复杂背包、掉落、任务、存档、匹配大厅、跨局成长和商业化 UI。
  • 射击回溯补偿、竞技级反作弊、助攻分、连杀分和复杂计分公式。
  • 多个 GameFeature 插件或为单次使用场景建立抽象工厂。

04　总体架构

配置不是“Experience 或配置文件”二选一，而是四层职责分离：

层级职责不应包含
地图 .umap场景几何、NavMesh、PlayerStart、带 SpawnGroup 标签的敌人出生点。技能逻辑、分数计算、波次状态。
Experience选择 PawnData、启用 Combat GameFeature、执行 Add Components/Input/UI 等组装动作、引用关卡定义。逐帧运行逻辑和大量数值调参。
UCombatLevelDefinition波次数组、敌人类型与数量、出生间隔、波次延迟、每次击杀分数、目标分数。运行中的剩余敌人数和当前分数。
.iniAssetManager 扫描、默认 GameMode/WorldSettings、GameplayTags、网络与技术默认值。单个关卡的波次和击杀分数。
启动关系：
L_Combat01 → WorldSettings 选择 B_Experience_CombatDemo → Experience 启用 CombatDemo GameFeature → 给 GameState 注入 UCombatLevelManagerComponent → 组件读取 DA_CombatLevel_01 → 仅服务器启动波次。

ASC 归属

  • 玩家：ASC 与核心 AttributeSet 放在 ADemoPlayerState，Character 作为 Avatar；这样 Pawn 重生时玩家能力身份可保留。
  • 敌人：ASC 与 AttributeSet 直接放在敌人 Character，生命周期与敌人一致。
  • 比赛状态：分数和波次不是 GAS Attribute；个人分数放 PlayerState，团队/波次状态放 GameState 组件。

06　核心类职责

类/资产职责与关键约束
UDemoExperienceDefinitionPrimary Data Asset；包含 GameFeature 列表、默认 PawnData、Actions/ActionSets，以及一个 UCombatLevelDefinition 引用。
UDemoExperienceManagerComponent挂在 GameState；服务器设置当前 Experience，复制标识，加载 Primary Assets，激活 GameFeature，完成后广播 ExperienceReady。
ADemoWorldSettings每张地图选择默认 Experience。只保存启动选择，不承担波次逻辑。
ADemoGameMode仅服务器存在；选择 Experience、处理登录与 Pawn 生成。Experience 未就绪前不生成玩家。
ADemoPlayerState拥有玩家 ASC、AttributeSets、PawnData 和个人分数；仅服务器授予 AbilitySet。
ADemoCharacter玩家 Avatar；在 PossessedBy 和 OnRep_PlayerState 初始化 ASC ActorInfo；输入转成 Input GameplayTag。
UDemoHealthComponent监听 Health Attribute，保证死亡只进入一次，触发死亡 GameplayEvent/Message；不自行决定击杀分。
UCombatLevelDefinition纯设计期数据：Waves、ScorePerKill、ScoreToWin。首版避免可选覆盖项和复杂继承。
UCombatLevelManagerComponentGameState Component；服务器生成敌人、推进波次、监听敌人死亡、更新复制的团队分与波次状态。
ACombatEnemySpawnPoint地图放置 Actor；含 SpawnGroup GameplayTag，供波次配置选择出生区域。
ADemoEnemyCharacter拥有敌人 ASC/属性；仅服务器 AI 控制与攻击。死亡后停止 AI、碰撞和能力，并通知关卡管理器。

必须覆盖的网络边界

  • 客户端不能通过 RPC 直接增加分数、宣告死亡或生成敌人。
  • 远端客户端看到的无敌和闪避表现可以稍后到达，但服务器收到伤害时只根据服务器 ASC 标签裁决。
  • 客户端 TargetData 必须校验射程、射击起点、方向容差、射速、弹药和目标合法性。
  • 晚加入客户端必须从 GameState/PlayerState 复制得到当前分数、波次和剩余敌人数。

闪避无敌规则

  1. 本地按键触发预测型 GA_Dodge，立即播放移动/动画表现。
  2. Ability 应用持续约 0.3 秒的 GE_DodgeInvulnerable，授予 State.Invulnerable。
  3. 所有正式伤害 GameplayEffect 的 Application Tag Requirements 阻止带有 State.Invulnerable 的目标。
  4. 服务器确认技能失败时，GAS 预测回滚；不能用客户端动画当前帧直接决定无敌。
  5. 首版使用固定持续时间。只有动画稳定后，才考虑 AnimNotify/GameplayEvent 精确控制无敌窗口。

10　关键运行链路

Experience 启动

地图加载 → Server GameMode 从 WorldSettings 获取 Experience ID → GameState 上的 ExperienceManager 加载资产与 GameFeature → 执行 Actions → 广播 ExperienceReady → 设置 PawnData并生成玩家 → LevelManager 启动第一波。

射击与伤害

客户端输入标签 → ASC 激活 GA_Weapon_Fire → 本地预测表现并提交 TargetData → 服务器检查能力、弹药、射速和射线 → 应用 GE_Damage → AttributeSet 扣血 → 属性复制与命中 GameplayCue。

闪避挡伤害

客户端预测激活 Dodge → 服务器确认并使目标拥有 State.Invulnerable → 敌人服务器攻击尝试应用 Damage GE → Application Tag Requirements 拒绝伤害 → 仍可播放擦过/闪避反馈，但不改变 Health。

敌人死亡与计分

Health ≤ 0 → 服务器 HealthComponent 原子式进入 DeathStarted → 从 EffectContext/Instigator 解析 Killer PlayerState → 广播一次 Message.Combat.Elimination → LevelManager 将击杀者个人分数和 TeamScore 各增加 ScorePerKill → RemainingEnemies-- → 复制 UI → 为 0 时推进下一波或结束比赛。

11　分阶段实施计划

规则：任何阶段编译失败或双人 PIE 核心验收失败时，不进入下一阶段。优先修正当前阶段，不通过堆新代码绕开问题。

阶段 0：新项目基线

实现：确认引擎版本与项目模块；启用 GameplayAbilities、GameplayTags、GameplayTasks、GameFeatures、ModularGameplay/ModularGameplayActors、EnhancedInput、AIModule、GameplayMessageRuntime、NavigationSystem 和 UMG。只添加实际需要的 Build.cs 依赖。

验收：Editor Development 构建通过；空地图可以双人 PIE；输出当前模块和插件清单。

阶段 1：最小 Experience + GameFeature

实现：DemoAssetManager、DemoExperienceDefinition、DemoExperienceManagerComponent、DemoWorldSettings、DemoGameMode、DemoGameState；创建 CombatDemo GameFeature Runtime 模块和 GameFeatureData；配置 Primary Asset 扫描。

验收：服务器选择 Experience；服务端和客户端各收到一次 ExperienceReady；CombatDemo 插件正确激活；Experience 未就绪前不会提前生成 Pawn。

阶段 2：玩家 ASC、PawnData 与输入标签

实现：PlayerState 拥有复制的 ASC（多人玩家建议 Mixed 模式）和属性；PawnData 引用 PawnClass、AbilitySet、InputConfig；Character 在服务器 possession 与客户端 OnRep_PlayerState 初始化 ActorInfo；服务器一次性授予 AbilitySet。

验收：两个客户端 ASC Owner/Avatar 正确；能力不重复授予；重生或重新占有不会产生重复 AttributeSet/AbilitySpec；输入标签能触发一个无伤害测试 Ability。

阶段 3：生命、伤害、死亡

实现：HealthSet、Damage Execution、HealthComponent、死亡事件和 State.Dead；伤害 EffectContext 保留 Instigator/EffectCauser；死亡只处理一次。

验收：只有服务器能改变最终 Health；两个客户端看到一致生命值和死亡；同一敌人不会重复发出死亡消息。

阶段 4：GAS 射击与换弹

实现：WeaponData/WeaponComponent 的最小弹药状态；GA_Weapon_Fire、GA_Weapon_Reload、伤害 GE、命中 GameplayCue；客户端提交 TargetData，服务器做射程、方向、射速和弹药验证。

验收：客户端射击有即时反馈；服务器决定命中和伤害；篡改/重复请求不能越过射速和弹药限制；远端客户端看到射击与受击表现。

阶段 5：闪避与 0.3 秒无敌帧

实现：GA_Dodge、GE_DodgeInvulnerable、冷却/体力条件（如果已有 Energy）以及伤害 Effect 的 Invulnerable 阻止标签。首版用固定时长，不先做同帧输入比较或回溯。

验收：闪避窗口内服务器拒绝伤害，窗口外正常受伤；高延迟 PIE 下不会由客户端单方面宣告无敌；预测失败能回滚。

阶段 6：主动技能

实现：至少一项与普通射击行为明显不同的技能，建议范围冲击或服务器投射物；包括 Cost、Cooldown、GameplayCue 和输入标签。核心稳定后再复制模板增加第二项技能。

验收：冷却与资源由服务器验证；客户端 HUD 正确显示；技能伤害同样服从 State.Invulnerable。

阶段 7：服务器 AI 敌人

实现：EnemyCharacter 自有 ASC；AIController、感知、简单追击/攻击 Behavior Tree；GA_Enemy_Melee 仅服务器执行；先在地图手工放置一个敌人测试。

验收：Dedicated Server 上 AI 正常运行；客户端不运行权威 AI；敌人能伤害玩家，玩家能击杀敌人，死亡后停止 AI 和攻击。

阶段 8：关卡 DataAsset、波次与计分

实现：UCombatLevelDefinition、Wave struct、SpawnPoint、GameState LevelManager；Experience 引用关卡定义；LevelManager 监听唯一的敌人死亡消息并更新个人分数、团队分数、RemainingEnemies 和 CurrentWave。

验收：两波配置按顺序生成；所有生成只发生在服务器；每名敌人只加一次分；晚加入客户端看到当前波次和分数；清空最后一波后结束比赛。

阶段 9：HUD 与比赛反馈

实现：Experience/GameFeature 添加 HUD；Widget 订阅 ASC 属性、冷却标签/效果、PlayerState 分数和 LevelManager 复制状态。不要让 Widget 保存权威游戏状态。

验收：双人 HUD 各自生命/冷却正确；个人分不同、团队分一致；波次和剩余敌人数与服务器一致。

阶段 10：多人回归与清理

实现：修复竞态、重复绑定、断线/晚加入问题；增加最小自动化或可重复控制台测试；清理仅由本次实现产生的未使用代码。不要顺便重构无关系统。

验收：Listen Server 2 人、Dedicated Server 2 人、模拟延迟/丢包、玩家死亡/重生、晚加入、连续两局均通过最终验收清单。

12　最终验收清单

  • 项目从干净构建状态成功编译，编辑器启动无模块/插件错误。
  • 地图通过 WorldSettings 选择 Experience，Experience 激活 CombatDemo GameFeature。
  • 两名玩家进入后 ASC、OwnerActor、AvatarActor、能力与属性均正确。
  • 射击、换弹、闪避和主动技能均通过 GAS 运行。
  • 闪避约 0.3 秒内服务器拒绝伤害，结束后伤害恢复。
  • AI 只在服务器决策，敌人状态正确复制。
  • 关卡 DataAsset 可修改波次数量、敌人数、生成间隔和击杀分数，无需改 C++。
  • 每名敌人死亡只计分一次；个人分与团队分只由服务器修改。
  • 晚加入客户端能看到正确分数、当前波次和剩余敌人。
  • HUD 不保存权威状态，只展示复制数据和 ASC 状态。
  • Listen Server 与 Dedicated Server 各完成至少一局。
